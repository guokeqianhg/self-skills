# 三分钟讲清项目

这一篇只回答三个问题：项目做什么、解决什么问题、价值在哪里。先能自然说清这三点，再进入实现细节。

## 一句话版本

> 这是一个把 性能采集平台 性能数据、录制截图和多模态模型结合起来的分析工具：它先用代码定位性能异常，再识别异常发生时的画面场景，最后生成有数据依据的异常解释、复测方案和可离线浏览的报告，同时还能独立发现性能曲线正常但画面异常的问题。

这句话中每一部分都对应实际代码：

- “用代码定位性能异常”：`core/telemetry.py`。
- “识别画面场景”：`core/scene_analyzer.py`。
- “解释和复测方案”：`core/event_analyzer.py`、`core/verification_planner.py`。
- “画面异常”：`core/visual_quality_scan.py`。
- “离线报告”：`core/report_renderer.py`。

## 30 秒版本：问题和价值

> 性能采集平台 能提供 FPS、FrameTime、CPU、温度和截图，但单看曲线很难知道一次波动发生在加载、战斗还是菜单，也很难快速判断下一步怎么验证。这个项目把性能异常和对应截图关联起来：先通过本地规则筛出真正值得关注的时刻，再让视觉模型说明当时在做什么，让语言模型结合实际采集指标给出分析和复测建议。这样测试人员拿到的不是分散曲线，而是一份按事件组织、能看到画面和证据的报告。另一方面，它单独扫描画面，因此可以发现 FPS 正常但白屏、贴图或 UI 出错的情况。

### 它具体替谁节省了什么工作

| 原有工作 | 项目减少的工作 | 仍然需要人工做的工作 |
|---|---|---|
| 人工翻曲线找可疑时间 | 代码按规则筛选慢帧、FPS、SevereJank、CPU、温度问题 | 确认阈值是否适合该产品 |
| 打开截图猜发生场景 | VLM 输出应用、场景和操作趋势 | 校验少见 UI 或识别不清画面 |
| 将多个指标和场景写成分析结论 | LLM 汇总已提供的指标与场景 | 验证根因，查看代码/埋点/日志 |
| 针对每个异常手工想复测步骤 | 按问题模式生成带观察指标和判读条件的方案 | 实际执行复测并记录结果 |
| 只看性能数据时漏掉画面问题 | 独立检查指定时段全部截图 | 对 suspect 和异常画面做最终确认 |

项目的价值在于减少“从数据到问题描述”的整理成本、让问题证据更完整、让复测有明确方向；不在于自动替代性能工程师做根因定案。

## 三分钟版本：自然完整的讲法

> 我做的是一个 性能采集平台 性能和截图的联合分析工具。性能采集平台 原本可以导出性能时序和截图，但两类信息是分开的：曲线告诉我们某个时间点掉帧了，却不告诉我们当时用户正在加载资源、切换界面还是对局操作；截图能看到画面，但没有性能上下文。
>
> 这个项目先读取 性能采集平台 的 JSON 或 Excel，云端场景也可以通过 MCP 拉取。无论数据从哪里来，都会转换成统一的内部数据结构，里面包含逐秒指标、逐帧 FrameTime、设备信息和截图关联。然后先用本地代码检测异常：例如根据本次录制推断目标帧率，用帧预算和统计阈值找明显慢帧；用多重条件找严重 FPS 下跌；直接读取 SevereJank；再检查高 CPU 和持续升温。这一步不依赖模型，所以规则可解释、结果可复现。
>
> 检测出的单条指标不会直接变成报告。程序会把同一截图、时间相近的多个异常合并为一个事件，因为一次卡顿可能同时有慢帧、SevereJank 和 FPS 下跌。异常太多时会选出覆盖不同类型和时间段的代表事件，避免把大量相似问题都发给模型。
>
> 对每个代表事件，程序只识别相关截图，而不是全量识别所有截图。视觉模型会结合当前截图和前后相邻帧，输出这是什么应用、什么场景、当时正在进行什么操作。随后文本模型做两阶段分析：第一轮只看核心性能快照和可用数据维度，选择需要继续看 GPU、内存或 CPU 等哪个方向；程序只取这些真实存在的细项，第二轮再生成最终解释。这样可以避免无关指标塞满上下文，也避免模型引用没有采集的数据。
>
> 多个事件完成解释后，系统按语义聚成问题模式，为每个模式生成一份人工可执行的复测方案。方案中要观察的指标必须来自本次实际采集数据，模型写错会被程序检查并要求重写。最后生成 JSON 和内嵌截图的 HTML 报告，测试人员可以离线打开查看。
>
> 除了性能主线，我还做了独立的画面异常扫描。它会检查选定时间段的全部截图，使用正常、可疑、异常三态，专门发现 FPS 正常但白屏、贴图缺失、画面遮挡过大或 UI 错乱的问题。由于画面判断有不确定性，系统保留可疑状态、要求模型给出可核查依据，并对整段时间轴做一次一致性核查。整体上，这是一个用确定性代码负责筛选和约束、用模型负责场景理解和辅助分析、并保留人工复核边界的工具。

## 面试中必须说清的边界

以下表达是准确的：

- “代码自动检测已经实现规则覆盖的性能异常，模型提供场景化解释和辅助判断。”
- “联合分析能提出有数据支持的可能方向，但不能只凭一次截图和少量指标证明根因。”
- “画面扫描判断画面状态是否需要关注，不直接判断底层渲染故障原因。”
- “复测方案是辅助测试人员执行和判读，不是自动完成复测闭环。”

以下表达不准确：

- “AI 自动找到了所有性能问题。”
- “模型看出 GPU 根因，所以根因已经确定。”
- “FPS 正常就说明体验和画面都正常。”
- “有 Function Calling 就等于模型输出一定正确。”
