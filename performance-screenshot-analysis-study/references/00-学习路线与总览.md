# 先读这里：学习路线与总览

## 这套材料要帮助你做到什么

读完后，应当能完成五件事：

1. 用一句话讲清项目做什么、解决什么问题、为什么有价值。
2. 从一份 性能采集平台 数据和截图开始，连续讲完程序怎样得到报告，不跳步骤。
3. 清楚说出哪些结果由代码规则确定，哪些结果由模型判断，避免夸大 AI 能力。
4. 被问到阈值、事件合并、缓存、下钻、并发、降级或视觉扫描时，能知道它在流程的哪一步、为什么这样实现。
5. 不看源码时仍能自然表达；需要深入时再用函数名回到对应实现。

这不是逐文件说明书。阅读顺序已经按面试叙述顺序排好：先理解项目价值，再理解完整流程，再理解关键设计，最后练习追问。

## 项目名称和核心定义

项目可称为：**性能采集平台 截图性能联合分析工具**。

它将三种信息放在一次分析中：

- 性能采集平台 性能时间序列：例如每秒 FPS、CPU、温度，以及逐帧 FrameTime、SevereJank。
- 性能采集平台 录制截图：告诉我们性能异常发生时应用画面是什么、用户正在做什么。
- LLM/VLM：将性能数字和场景解释整理为可读结论、复测建议和画面质量结论。

项目的核心输出不是“某一时刻 CPU 是多少”，而是：**在什么场景、什么时刻、出现了什么性能或画面问题；现有数据支持什么判断；下一轮如何复测。**

## 先记住的四条原则

### 原则 1：先由代码发现候选问题，再让模型解释

程序不会把整份曲线直接交给模型，让模型自行找异常。它先在本地解析数据，并根据明确阈值检测慢帧、严重卡顿、严重掉帧、高 CPU 和持续升温。这个阶段结果由相同输入和相同代码决定。

模型只在候选问题已经筛出来后参与。这样减少成本，也让“为什么这一点被认为异常”可以回到代码规则解释。

### 原则 2：性能异常和画面异常是两条不同的检查路径

性能主线检查数值是否异常，例如 95ms 的慢帧、18 FPS、SevereJank。画面扫描检查玩家是否看到不正常的画面，例如白屏、贴图缺失、UI 错乱。FPS 正常不能证明画面正常；发现白屏也不能仅凭截图证明 CPU 或 GPU 根因。因此两条路径独立运行、独立展示。

### 原则 3：模型可以提出判断，但不能突破数据边界

模型可以说“从当前场景和指标看，可能怀疑 GPU 或内存”；程序再只提供实际采集到的细项。若 GPU 利用率没有采集到，最终结论不能把“GPU 利用率高”当事实。模型的根因文字是分析假设，不是自动证明。

### 原则 4：结构、校验、缓存和兜底比模型文本本身更重要

模型输出必须进入预定义字段；必要时会检查是否漏掉图片、漏掉事件、编造指标或结构不完整。失败会重试；仍失败时部分功能使用固定逻辑保证报告可以继续生成。画面可疑状态保留给人工复核，不把模型判断写成最终裁决。

## 学习时统一使用的术语

| 术语 | 这里具体指什么 |
|---|---|
| 采样点 | 一秒左右的性能记录，保存 FPS、CPU、温度、截图名等 |
| 逐帧数据 | 每帧真实耗时，主要用于找瞬时慢帧 |
| 异常点 | 一项规则在一个时刻命中，例如“101.2 秒 FrameTime 95ms” |
| 异常事件 | 将同一画面、时间接近的多个异常点合成一次问题，例如慢帧和 SevereJank 同时发生 |
| 场景识别 | VLM 识别截图中的应用、平台、画面状态和当前操作趋势 |
| 联合分析 | 将事件的性能数据和场景文字交给 LLM，生成解释 |
| 下钻 | 第一轮模型认为 GPU/内存/CPU 等某维度值得看后，代码只取该维度细项继续分析 |
| 复测方案 | 对一类相似事件给出的人工验证步骤和结果判读方式 |
| 画面扫描 | 不依赖性能阈值，对指定时间段全部截图判定 normal/suspect/abnormal |

## 建议的复习节奏

第一次阅读：按 01 → 02 → 03 → 04 → 05 连续读完，只记住主线，不背数字。

第二次阅读：以“100 秒出现一次卡顿”为例，从 `02` 顺着数据变化走一遍；随后看 `03`，理解为何阈值、事件和下钻这样设计。

第三次阅读：不看文档，用 3 分钟讲项目；再打开 `05` 对照追问补弱点。被问到具体函数时，再根据每节的“实现定位”回到代码。

## 代码目录与职责，只需先有基本印象

```text
pipeline.py                     主流程编排入口
core/telemetry.py               解析 性能采集平台 数据、检测和合并性能异常
core/scene_analyzer.py          调用视觉模型识别截图场景
core/event_analyzer.py        调用文本模型做两阶段联合分析
core/verification_planner.py        聚类问题并生成复测方案
core/visual_quality_scan.py           独立扫描画面异常
core/platform_mcp_client.py           请求 性能采集平台 公网 MCP
core/remote_data_source.py          将云端数据转换为内部性能数据
core/report_renderer.py                生成内嵌截图的 HTML 报告
core/model_usage.py           统计模型 token
scene_cli.py                        单图或目录场景识别入口
build_scene_archive.py          全量截图场景存档入口
review_visual_scan.py               只重跑画面扫描的整段核查
image_video/image_to_video.py  独立图片转视频工具
```
