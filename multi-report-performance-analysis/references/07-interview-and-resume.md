# 07. 面试复习与简历表述附录

> 本文件是技术档案的派生材料。准备面试时先复习 01~06，再用本文件组织表达。

## 1. 30 秒项目介绍

这个项目做的是 性能分析平台 的多报告 AI 性能分析。业务方一次传入 2 到 5 份报告，指定跨版本、跨机型或跨平台等 7 类对比场景，后台的 LangChain Agent 通过 MCP 调用 性能分析平台 数据工具，采集 FPS、Jank、内存、CPU/GPU 等指标，对异常时段继续下钻，最终输出 9 模块结构化对比报告。

我负责的重点是让结果可交付：模型负责分析和归因，程序从 MCP ToolMessage 回放原始统计数据，回填核心数值并重算派生指标；再通过 Zod 校验、定向重试和 module8/9 二次复审，降低数值和结论不一致的问题。

## 2. 高频问题：为什么不直接让模型写报告？

模型能根据数据写出看起来合理的结论，但它不适合承担确定性部分。多报告 JSON 里有大量可验证数字，模型可能抄错 case、混淆统计口径或补全缺失值。

所以实现上把职责分开：ReAct Agent 负责决定取哪些数据、异常如何解释；本地 `normalizeCoreMetricsFromToolData()` 从 MCP 原始结果按 caseId 回填 FPS/Jank/内存/CPU/GPU，达标率和内存占用率由程序重算。没有可靠来源就输出 null，不保留模型猜测值。

## 3. 高频问题：为什么要做 module8/9 二次复审？

数值回填会纠正模型的草稿，但模型原先生成的根因和优化建议可能仍引用旧数字。代码先把校正前后的高影响事实做 diff；没有变化直接保留，变化较小时用辅助模型做 KEEP/REVISE 判断，变化大或方向受影响时才让主模型定向重写根因和建议。

这样避免了两种极端：每次都全量重写，成本太高；完全不复审，建议可能和最终数据矛盾。

## 4. 高频问题：如何让 JSON 稳定？

使用 Zod 的 `multiReportSchema` 定义 9 模块结构；非 Anthropic 模型在最终输出时由 structuredOutputRetryMiddleware 从 content/reasoning 提取 JSON、修复常见数组/对象层级错误、执行 safeParse，并按“未采集数据、Schema 不通过、没有 JSON”三类失败生成不同重试提示，最多 2 次。

Claude 分支使用模型侧 JSON Schema 输出；其他模型使用应用层兜底。工具 Schema 还会先清洗，避免不同网关因为 `$schema` 或 nullable union 直接拒绝工具调用。

## 5. 高频问题：如何控制 Agent 时间和重复调用？

Prompt 对模型给出阶段预算：先采集、再判异常、再下钻、最后输出，不要在最终阶段反复调工具。代码层用 toolDedupeMiddleware 按工具名和稳定序列化参数拦截相同 MCP 调用，设置 `recursionLimit=30` 限制图执行步数；工具失败最多重试 3 次，空响应/5xx/网络超时等上游瞬态错误最多重试 2 次并进行指数退避。

目标 8 分钟、最长 15 分钟是 prompt 预算。回答时不要说代码已实现完整 15 分钟硬超时。

## 6. 高频问题：为什么 `compareType` 由业务方传入？

比较目的不完全能从报告元信息推断。两个相似报告可能是重复测试，也可能是版本回归验证。跨版本、跨设备、跨平台的分析重点不同，因此由调用方传 compareType，后端映射为内部枚举，模型负责在既定场景下解释可比性和差异。

## 7. 可验证数字

- 支持 2~5 份报告。
- 支持 7 类对比场景。
- 输出 9 模块 JSON。
- 结构化输出最多 2 次重试。
- 工具错误最多 3 次重试。
- 上游瞬态错误最多 2 次重试。
- Agent recursionLimit 为 30。
- module8/9 高影响事实变化超过 24 项时直接完整修订。
- 有 drop context 时每报告最多重建 3 个异常项，全局最多 10 项。

## 8. 可用的简历表述

```text
基于 LangChain + ReAct 搭建 性能分析平台 多报告性能分析 Agent，通过 MCP 接入平台数据服务，支持 2~5 份报告、7 类对比场景的自主工具调用与性能归因；模型输出后按 caseId 回放 MCP 原始数据回填核心数值并重算派生指标，使用 Zod 校验 9 模块 JSON，结合两级复审、定向重试、工具去重和上游退避保障长链路稳定交付。
```

## 9. 不应夸大的内容

- 不说“自动判定 7 类场景”，真实逻辑是调用方传入 compareType。
- 不说“完整多模态截图识别已在多报告主链路实现”。
- 不说“15 分钟硬超时已由代码保证”。
- 不说“绝对不产生幻觉”或“100% JSON 成功”，当前实现是校验、回填和降级机制，不是绝对证明。
- 不填未实测的准确率、耗时、成本降低百分比。
